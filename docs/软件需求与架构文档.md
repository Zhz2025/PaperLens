# PaperLens 论文 PDF 阅读器 —— 软件需求与架构文档

> 项目暂定名：**PaperLens**（可随时修改）
> 文档状态：已经双视角评审（需求完整性 / 技术可行性）| 最后更新：2026-08-16

---

## 1. 产品概述

**定位**：面向科研人员/研究生的学术 PDF 阅读器。核心体验 = **翻译 + 生词 + 批注** 三位一体，重阅读体验与美术质感。

**形态**：Windows 桌面应用（Tauri v2 打包 .exe + 本地 Python sidecar），**完全离线运行**，不依赖任何云服务。支持本地注册多个账号，账号间数据完全隔离。未来若面向公众发布，同一套后端代码可平移云端部署。

**目标用户**：非英语母语论文读者、英语学习型研究者。

**核心价值**：

1. 学术词汇语境翻译（**内嵌本地 LLM**（llama.cpp 内核）结合上下文，解决 "attention 到底是注意力还是关注" 这类词义消歧）
2. 生词自动高亮 + 间隔重复复习（越读越熟的词库）
3. 类 MarginNote 连线批注（选中词 → 连线 → 页边卡片）
4. 扫描版 PDF 通过本地 OCR 变为可选中、可翻译（RapidOCR，纯 CPU）
5. 纯本地：数据不出本机，零 API 费用，断网可用

## 2. 关键决策记录（ADR）

| 编号 | 决策项 | 选定方案 | 被否备选及理由 |
|---|---|---|---|
| D1 | 部署形态 | 纯本地多账号（本地注册、数据隔离），架构预留云端迁移路径 | ①远程后端+云同步：V1 复杂度高、需服务器成本，否；②单账号无密码：需求方要求多账号隔离，否 |
| D2 | 本地后端 | FastAPI sidecar（PyInstaller 打包，随 Tauri 启动）+ SQLite（WAL） | ①Rust 直连 SQLite + Python 仅 OCR：业务逻辑割裂三处，否；②无后端纯前端：OCR/写回 PDF 工程碎，否 |
| D3 | OCR 引擎 | RapidOCR（ONNX Runtime CPU；3.9.2 默认 PP-OCRv6 det/rec small + cls PP-OCRv4 mobile，whl 27MB 内置模型离线开箱；rapidocr+onnxruntime whl 合计 ~41MB） | ①MinerU：AGPL 许可 + 磁盘 20GB+，否；②PaddleOCR 完整框架：~500MB 依赖，否；③PaddleOCR-VL：需 GPU 8GB+，否；④Tesseract：学术文档精度弱、多栏版面差，否。⚠️ 运行硬依赖 opencv-python 等（安装态合计 ~350MB），原"OCR<100MB"口径仅覆盖 whl 本体，已并入 <1GB 总预算（见第5章） |
| D4 | 翻译引擎 | 全离线：ECDICT 词典 + 内嵌本地 LLM（语境消歧），不内置任何在线引擎 | ①Google 官方 API：要钱（免费额度需绑信用卡），否；②Google 非官方免费端点：非官方有限流风险，否；③DeepL Free：需注册 key 且联网，否（均可在 V2 作为可选引擎加回） |
| D5 | LLM 推理引擎 | **sidecar 进程内嵌 llama-cpp-python 0.3.34**（llama.cpp 官方 Python 绑定；**装 GitHub Release 预编译 CPU wheel**（py3-none-win_amd64，6.3MB，含 AVX2）——PyPI 仅 sdist，裸 pip 会触发本地 CMake 编译）：单模型串行推理、显式热载/卸载、GGUF 内嵌模板默认非思考 | ①打包 Ollama 运行时：体积 300-700MB 且服务化/并发/模型库管理对"单模型非思考"需求全冗余，keep_alive 控制粒度粗，外部进程管理与 11434 端口冲突，否；②transformers 直跑：CPU 性能远逊 llama.cpp 量化内核，否；③vLLM：面向 GPU 服务端部署，否。默认模型 unsloth/Qwen3.5-2B-GGUF 的 Q4_K_M（**1.19GiB**；Qwen3.5 为单一混合双模式模型，无独立 instruct 变体，官方模板 `enable_thinking` 未定义时预填空思考块=**默认非思考**；设置页可切 0.8B Q4_K_M（508MiB）提速档） |
| D6 | 内存约束 | 稳态（日常阅读、**模型未加载**，含前端）<400MB；模型加载态为用户主动选择（**增量** +~1.8GB：权重 1.19GiB + KV cache + logits 缓冲，叠加稳态后 sidecar 总量 ~1.9GB 见 §6.2），默认空闲 10 分钟自动卸载回落；OCR worker 仅运行时存在，结束即退出 | ①严格恒 <400MB（模型常驻也禁止）：失去大模型语境翻译能力，否；②模型默认常驻：空闲时白占 ~1.8GB 内存，否 |
| D7 | PDF 处理库 | pypdfium2（页面渲染/文本提取，给 OCR 用）+ pypdf（批注写回） | ①PyMuPDF：API 最强但 **AGPL-3.0**，面向公众闭源商用有风险，列为备选（若接受开源可换回） |
| D8 | 桌面壳 | Tauri v2（Rust 薄壳 <500 行） | ①Electron：零 Rust 但安装包 ~100MB、内存高，否 |
| D9 | 多设备同步 | V1 不做；提供导出/导入备份；V2 预留（WebDAV 或自建云） | ①V1 就做同步：纯本地架构下复杂度不成比例，否 |

## 3. 名词表与非目标

**名词表**

| 名词 | 含义 |
|---|---|
| sidecar | 随主程序启动的本地 Python 后端进程（HTTP 服务） |
| OCR worker | 独立 Python 子进程，仅在做扫描版解析时存在，空闲自动退出 |
| lemma | 词元（单词归一化形式，如 studies → study） |
| 术语表 glossary | 从单篇论文自动抽取（TF-IDF）+ 用户修正沉淀的高频学术词及其译法 |
| 锚点 anchor | 批注所指向的原文区域（页码 + 矩形坐标集合） |
| 用户空间坐标 | PDF 标准坐标系：单位 pt（1/72 英寸），原点在页面**左下角** |

**V1 非目标（明确不做）**

- 云同步 / 多设备实时同步（V2 预留）
- 移动端、Web 版、协作批注
- OCR 公式转 LaTeX、表格结构还原（扫描版公式/表格区域仅按原样显示，文本区可选中）
- 阅读器内嵌 AI 问答/摘要对话

## 4. 功能需求

> 每条 FR 附验收标准（AC），里程碑完成以 AC 全部满足为准。

### FR-1 本地账号系统

- 本地注册/登录：用户名 + 密码（BCrypt 哈希），无邮箱、无网络验证
- 可创建多个本地账号，所有业务表按 `user_id` 隔离；切换账号需重新登录
- 会话：不透明随机 token（256-bit）存 SQLite `sessions` 表，"记住我" 30 天 / 未勾选 24 小时；退出登录即删除
- 首启动向导：创建首个账号 + 选择数据目录（本机定制默认 `E:\PaperLens\data`；目录可迁移）+ 推荐模型下载（可跳过，稍后可在设置中下载或手动导入 GGUF）

**AC**：注册两个账号 A/B，A 上传的论文/批注/生词在 B 登录后完全不可见；杀进程重启后仍在登录态。

### FR-2 文库与项目

- 项目管理：创建/重命名/删除/拖拽排序
- 拖拽或选择 PDF 上传：文件复制到 `{数据目录}/files/{file_hash}.pdf`（**全局**按内容 hash 去重，跨账号共享同一物理文件；账号隔离由数据库 `user_id` 列保证）
- 元数据：标题自动提取（PDF Info 或首页最大字号文本行），作者/年份/标签/备注可手动编辑
- 视图：最近打开、收藏、按项目/标签过滤、按上传时间/标题排序
- 删除论文 = 确认框后硬删除：级联删除 annotations / word_occurrences / glossary_terms / translation_cache / reading_progress / reading_sessions / excerpts / OCR 结果（**words 生词本体保留**）；`file_refs.ref_count` 事务内减一，归零则删物理文件

**AC**：上传 50MB PDF <3s（本地拷贝）；同文件二次上传不占额外空间；删除后文件目录中无孤儿文件。

### FR-3 PDF 阅读器

- pdf.js 渲染；单页 / 连续滚动两种模式，记住偏好
- 缩放（Ctrl+滚轮、Ctrl+=/-、适应宽度）、页码跳转、目录大纲（书签）、页内搜索（高亮所有命中 + 计数 + Enter 跳转）
- 阅读进度自动保存（页码 + 滚动位置，节流 2s），重开恢复
- 深色/浅色/暖纸三主题 + 跟随系统；字体大小可调（正文重排不适用，仅 UI 字号）
- 长文档（≥200 页）懒渲染：仅渲染视口 ±2 页，滚动无白闪（预渲染下一页）

**AC**：300 页 PDF 连续滚动不卡顿（肉眼无明显掉帧，滚动时 CPU 占用 <30%）；断电重启后回到原位置。

### FR-4 划词翻译（全离线）

- 选中文本 → 浮动工具条（翻译/释义/入生词库/批注，图标按钮）
- 命中顺序（四层）：
  1. **个人词库**：该词已入生词库且带译法 → 直接出卡，0 延迟；若本文术语表存在用户修正（source=user）则**以修正译法为准**并附"本文术语"徽标（修正优先级最高的裁决规则）
  2. **本文术语表**：TF-IDF 预译结果 → 出卡并显示"本文术语"徽标，0 延迟
  3. **翻译缓存**：`(user_id, paper_id, lemma, engine)` 命中 → 0 延迟
  4. **ECDICT 词典 + 内嵌 LLM 并行**：ECDICT 基础词义毫秒级先显示，LLM 语境译法流式追加（SSE）
- 翻译卡片分区：词性+基本义（ECDICT）｜本文语境译法（LLM，流式）｜句译（选句时）｜原句上下文折叠
- 选句翻译：同走 LLM（带上下文 Prompt）；句译缓存以 `sentence_hash`（句文本 SHA-256）为键，与词缓存同表、不同唯一键
- 模型未下载/未加载：首启动向导或设置页引导下载（ModelScope 国内源优先，HuggingFace 备选，断点续传）或手动导入 GGUF；期间 ECDICT/术语表/缓存层照常可用，首次 LLM 请求自动触发后台加载（先出词典释义，加载完成后续流）

**AC**：ECDICT 命中 <50ms 出卡；模型就绪态 LLM 首 token ≤3s（约 600 token prompt，非思考默认模板；附录A基准机 M0 实测校准）；同词二次查询 <50ms；拔网线全流程可用；卸载模型后再次划词 → 自动重新加载且词典释义不中断。

### FR-5 学术语境处理（核心差异化）

- **上下文注入**：LLM 请求携带 单词所在句 + 前后各 1 句 + 论文标题（+摘要若有）+ 本文术语表命中项
- **术语表自举**：文本型 PDF 上传完成后后台任务跑 TF-IDF（1-2 gram，去停用词，top 30），批量 LLM 预译入术语表（空闲时段低优先级执行，可取消）；扫描版在 OCR 完成后触发
- **用户沉淀**：用户在翻译卡片上修正译法 → 写入术语表（source=user，优先级高于 tfidf）
- 全文任何位置再划该术语 → 术语表层命中，带"本文术语"徽标；**用户修正（source=user）优先级最高**：即使该词已入个人词库，也以修正译法为准（见 FR-4 层1 裁决规则）

**AC**：上传一篇 arXiv 论文，5 分钟内术语表生成（后台）；修正 "transformer→变换器" 后，翻到第 20 页划 "transformer" 立即显示修正译法 + 徽标。

### FR-6 生词库

- 划词一键入词库（自动附：当前译法、原句、上下文翻译、paper_id）
- 三级状态：**陌生**（橙色底高亮）/ **学习中**（鹅黄底）/ **已掌握**（绿色点状下划线）
- **SM-2 间隔重复**：复习队列按 `due_at` 排序；复习卡片回显原句语境（来自 word_occurrences）
- 正文自动高亮：打开 PDF 即按当前账号词库匹配渲染（lemma + 词形还原匹配）
- 词形处理：大小写归一 + 规则还原（复数/时态/比较级）+ 常见不规则动词表
- 手动/自动升阶：最近两次复习记录（review_logs）均为"记得"（q=5）且 interval ≥ 21 天 → 提示可标记已掌握；答"忘了"（q=2）时 stage 降 1 级（不低于 0）
- 导出 CSV / Anki 可导入的 TSV 文本格式（含 Separator/HTML 设置说明；不生成 .apkg 包）

**AC**：词库 500 词时打开 30 页论文，高亮渲染 <1s（当前页）；SM-2 到期列表正确（用固定时钟单测）；导出 CSV 用 Excel 打开无乱码（UTF-8 BOM）。

### FR-7 批注系统

- **连线批注（词/句级）**：选中 → 浮动条点"批注" → 从锚点拖出贝塞尔曲线 → 页边任意位置松手落卡片 → 卡片内写笔记/贴译文；卡片可拖动/缩放/编辑/删除；点击卡片↔锚点互跳；Esc 取消连线
- **句子批注**：五色高亮（黄/绿/蓝/粉/紫）+ 页边卡片或句尾折叠
- 批注侧边栏：全部批注列表（页码 + 摘录文本 + 卡片内容），按颜色/类型/关键词过滤，点击定位
- **写回 PDF**：导出副本 = 原文件 + 标准批注（高亮 + Popup 文本注释），WPS/Adobe/Chrome 可打开编辑；连线卡片导出时降级为"高亮 + 弹窗注释"
- 批注数据全存 SQLite（跨账号隔离）

**AC**：缩放/滚动/翻页后连线与锚点不错位（坐标存 PDF 用户空间）；导出的 PDF 在 WPS 与 Adobe 中高亮可见、弹窗可编辑。

### FR-8 OCR（V1，RapidOCR）

- 上传时检测：前端 pdf.js 均匀抽样 3 页（约第 N/4、N/2、3N/4 页）textContent，平均字符数 <100/页 → 判定扫描版；论文详情页可手动覆盖判定（PATCH `is_scanned`）后触发或跳过 OCR
- 扫描版自动入 OCR 队列；OCR 在**独立 worker 子进程**运行（单并发，空闲 60s 自动退出）
- 输出：每页文本块列表 `{bbox(PDF 用户空间), text, conf}`；行级结果按列聚类为段落块（启发式：x 重叠 + 行距阈值）
- 前端将 OCR 文本渲染为透明叠加层：绝对定位 span 与原图对齐，可选中/划词/高亮/批注，体验与文本型一致
- 状态可视化：排队 / 解析中（进度 = 已完成页/总页数）/ 完成 / 失败（可重试，重试跳过已完成页）
- 解析结果缓存至 `{数据目录}/ocr/{paper_id}/blocks.ndjson` + 数据库索引；删除论文一并删除

**AC**：20 页扫描论文在纯 CPU 上完成解析（外推 1-5 分钟：单页 2-6s@8 核 / 5-15s@4 核，M0 实测为准）；叠加层文字与原图目视对齐（偏差 <2px @100% 缩放）；OCR 运行时任务管理器可见 worker 进程，完成后 60s 内消失。

### FR-9 阅读记录与统计

- 每篇论文：累计阅读时长（窗口失焦暂停计时）、打开次数（`papers.open_count`，打开时 +1）、上次位置
- 统计面板：最近 30 天阅读日历热力图、今日/累计时长、生词新增曲线、复习完成率（今日已复习数 / 今日到期数，数据源 review_logs）
- 会话记录：`reading_sessions`（start/end/duration），统计页可按日聚合

**AC**：时长统计与实际偏差 <5%（失焦不计时的单测）；热力图数据与 sessions 表一致。

### FR-10 摘录与导出

- 复制选中文本自动附引用：`作者 (2025), p.3`（作者缺失时用标题前 20 字）
- 摘录（原文+译文+我的笔记）一键保存，导出 Markdown（Obsidian 兼容格式）
- 生词库导出 CSV/Anki；批注导出（PDF 写回 + Markdown 列表）

**AC**：导出的 Markdown 在 Obsidian 打开，高亮块引用与嵌套笔记渲染正常。

### FR-11 设置

- LLM 模型管理：推荐模型下载（内置清单：Qwen3.5-2B Q4_K_M（unsloth）默认 / 0.8B Q4_K_M 提速档，ModelScope 源优先）、手动导入本地 GGUF、多模型列表切换；**加载策略**（用完即卸 / 空闲 10 分钟自动卸载（默认）/ 常驻）；手动"立即加载/卸载"按钮；状态徽标（未加载/加载中/就绪 + 当前内存占用）
- ECDICT 词典信息（完整版预置，约 340 万词条）
- 生词高亮：开关、三档样式强度、仅标注当前论文出现过的词
- 批注：默认颜色；主题；快捷键查看（V1 不可改键）
- 数据：数据目录查看/迁移（复制 → 校验 → 更新配置 → 删原目录，任一步失败保留原目录）、备份导出/导入、缓存清理（`DELETE /api/cache/{type}`，type=ocr|translate 分别清理）

**AC**：迁移数据目录后所有功能正常（PDF 能打开、批注在）；备份导出 zip → 新装机导入后账号/论文/批注/生词完整恢复。

## 5. 非功能需求

| 项 | 量化要求 |
|---|---|
| 内存 | 稳态（**模型未加载**，含 WebView 前端）**<400MB**；模型加载态 sidecar 额外 +~1.8GB（Q4_K_M 权重 1.19GiB + KV cache + logits 缓冲：Qwen3.5 词表 248,320，库预分配 (n_batch×n_vocab) float32——n_batch=512 时 ~508MB、**128 时 ~127MB**，故锁 128），用户主动加载、空闲 10 分钟自动卸载回落；OCR worker 仅运行时存在，峰值另计 300-500MB，结束即退 |

### 6.5 安全设计（本地）

- sidecar 绑定 `127.0.0.1:8737`（固定端口，仅本机可访问）。**鉴权单层**：session token——登录颁发、存 sessions 表，**所有业务请求**携带 `Authorization: Bearer {session_token}`。启动握手 token 机制**预留未启用**：Rust 壳仍生成随机 token 写入 `{数据目录}/.token` 并以 `PAPERLENS_BOOT_TOKEN` 注入 sidecar 环境，但后端不校验；仅为未来启用归属校验保留接口
- sidecar 开启 CORS（允许 `http://tauri.localhost` 生产源与 `localhost:5173`/`127.0.0.1:5173` 开发源）；Tauri CSP 放行 `connect-src http://127.0.0.1:*`；SSE 前端用 fetch ReadableStream 实现（EventSource 不支持 POST 与自定义头）
- sidecar 二进制按 Tauri externalBin 规范带 target-triple 后缀（`paperlens-server-x86_64-pc-windows-msvc.exe`）；Rust 侧 spawn 后立即挂 Windows Job Object（`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`，windows-sys 自实现——tauri-plugin-shell 的 kill 仅杀直接子进程、无级联），应用退出走**单级终止**：kill 直接子进程 → 关闭 Job Object 句柄级联终止整个进程树（无优雅 HTTP shutdown 步骤，后端无 shutdown 端点）
- 所有文件访问路径必须落在 `{数据目录}` 内（resolve 后前缀校验），防目录穿越
- 密码 BCrypt(cost=12)；不上传任何数据

## 8. 核心机制详细设计

### 8.1 翻译链路（四层命中 + SSE）

```
划词 → 前端归一化(lowercase+lemma) → 单次 POST /api/translate/word (SSE)
  server 内部依次判定层①-③，命中即发 hit 并直接 done（不再调 LLM）：
  ① 个人词库命中（若术语表有 source=user 修正则以其为准 + 徽标）
  ② 本文术语表命中（tfidf 行）→ hit + "本文术语"徽标
  ③ 翻译缓存命中 → hit
  ④ 全未命中：
       event: hit    {"layer":"ecdict","pos":"n.","phonetic":"...","gloss":"注意;关注"}   ← 毫秒级先出
       event: delta  {"text":"本文语境:"}                                                  ← LLM 流式
       event: delta  {"text":"注意力机制。"}
       event: done   {"engine":"llm-qwen3.5-2b-q4km","cached":false}
     仅 LLM 结果写入 translation_cache；同词同文再查走 ③
  异常与取消协议：
       event: error  {"code":"llm_loading_timeout|llm_timeout|internal","detail":"..."}
                      ← LLM 层失败；此前已发的 ECDICT hit 内容保留展示
       前端划新词 → AbortController 取消上次请求；sidecar 感知连接断开即终止当前 LLM 生成（推理队列取下一任务）
       event: ping  每 10s 空事件（WebView2 长连 SSE 存在静默掉线实锤，心跳保活；前端 15s 无任何事件判死链自动重连）
       done 前断流（前端 3s 无新事件）→ 保留已收内容 + 显示重试按钮
```

**LLM Prompt 模板**（词义消歧核心；句译模板类同）：

```
你是学术翻译助手。只输出规定分区，不要解释。
论文标题: {title}
本文术语表(节选): {glossary_hits}
当前句: {sentence}
上文: {prev_sentence}
下文: {next_sentence}

解释单词 "{word}"，按以下分区输出：
【词性】
【基本义】
【本文译法】结合上下文给出最贴切的中文译法，并说明理由（一句话）
【领域词】是/否 + 若是，所属领域
```

- LLM 调用（进程内嵌 llama-cpp-python，设计见 8.1.1）：`create_chat_completion(messages, stream=True, max_tokens=300, temperature=0.3, top_p=0.8, top_k=20)`（top_p/top_k 取 Qwen 官方非思考推荐采样域；库默认 temperature=0.2/top_k=40 与官方推荐不符，**须显式传参**）
- 流式按行解析分区标记，`【`开头的行触发卡片分区切换
- 超时 30s 无首字 → 发 `error` 事件（llm_timeout）；ECDICT 层结果保留

### 8.1.1 内嵌 LLM 推理引擎（llama-cpp-python）

**定位**：进程内单模型推理服务，替代外部 LLM 进程（Ollama 等）。需求极简——单模型、非思考、串行流式，因此不引入任何服务化层。

```
LLMService（sidecar 进程内单例）
├─ 模型生命周期
│   ├─ load(model_id)   后台线程加载（首次 5-15s, mmap），状态: loading→ready
│   ├─ unload()         llm.close()→del→gc.collect()；RSS 回落
│   │                     (Windows 分配器可能延迟归还 OS,sidecar 重启兜底)
│   ├─ 切换模型         unload → load（串行）
│   └─ 空闲自动卸载     默认 10 分钟无请求（可配 0=用完即卸 / -1=常驻）
├─ 推理队列
│   ├─ asyncio.Lock 串行（单模型无并发收益, 队列防显存/内存超卖与结果串流）
│   └─ 翻译请求 / 术语表批量预译 共用同一队列
└─ 未加载时请求行为
    └─ 自动触发后台加载; 本次请求先出 ECDICT hit, 60s 内加载完成则续流 LLM,
       超时发 error(llm_loading_timeout), ECDICT 内容保留
```

**关键实现参数（llama.cpp 内核调优）**：

| 参数 | 值 | 理由 |
|---|---|---|
| `model_path` | `Qwen3.5-2B-Q4_K_M.gguf`（unsloth） | 1.19GiB（实测字节数 1,280,835,840），质量/速度/内存最佳平衡 |
| `n_ctx` | 4096 | 翻译 Prompt ≈ 500-800 token，KV cache 省内存 |
| `n_threads` | 物理核数（非逻辑核） | 库默认 None≈逻辑核数，显式覆盖；llama.cpp 实测超线程反而降速 |
| `n_batch` | **128** | Qwen3.5 词表 248,320：库预分配 (n_batch×n_vocab) float32 logits 缓冲——512→~508MB、128→~127MB，必须压低；M0 对比定档 |
| `use_mmap` | True | 权重按需换页，加快冷加载 |
| `use_mlock` | False | 默认允许换出，降低常驻压力 |
| chat template | `chat_format` 不传 → 自动应用 GGUF 内嵌 Jinja 模板 | Qwen3.5 官方模板 `enable_thinking` 未定义时**预填空 `<think>` 块=默认非思考**（官方设计，实测 GGUF 元数据确认）；保险：包装 chat_handler 显式注入 `enable_thinking=False`（`create_chat_completion` 无 per-request `chat_template_kwargs`，该参数仅 server 侧存在） |
| 指令集 | AVX2（预编译 wheel 自带，无 AVX512） | 2013 年前无 AVX2 的 CPU 不可用；AVX-512 收益 M0 实测后决定是否自编译 |

**模型分发**：不随安装包。首启动向导/设置页下载（断点续传 + sha256 校验，直链免登录已实测）：ModelScope `modelscope.cn/models/unsloth/Qwen3.5-2B-GGUF/resolve/master/Qwen3.5-2B-Q4_K_M.gguf`（国内优先）/ HuggingFace `huggingface.co/unsloth/Qwen3.5-2B-GGUF/resolve/main/Qwen3.5-2B-Q4_K_M.gguf`；Q4_K_M sha256 = `aaf42c8b7c3cab2bf3d69c355048d4a0ee9973d48f16c731c0520ee914699223`。亦可手动导入本地 GGUF 至 `{数据目录}/models/`；推荐清单含 0.8B Q4_K_M（508MiB）提速档。

### 8.2 术语表自举（TF-IDF）

- 触发：文本型 PDF 上传完成后 / 扫描版 OCR 完成后，入低优先级后台队列（单任务，可取消）
- 文本源：pypdfium2 提取全文（用 `get_text_bounded`——`get_text_range` 受 UCS-2 限制；扫描版用 OCR 结果）
- 抽取：小写化 → 1-gram + 2-gram → 去停用词表（内置学术英语停用词）→ TF-IDF 排序 → top 30
- 预译：每次 10 词批量 Prompt（限输出 JSON），失败重试 1 次，失败的词留空（划词时现查）
- 用户在卡片修正译法 → `glossary_terms.source=user` 覆盖 tfidf 行

### 8.3 词形还原（前端 TypeScript）

```
归一化: word.toLowerCase()
规则还原(存在性验证由 server 查 ECDICT——主数据源 lemma.en.txt 词形库(BNC 全语料生成,官方称95%覆盖,含 gave→give/teeth→tooth),辅以词条 exchange 字段; 经 GET /api/dictionary/{lemma} 返回, 依序尝试):
  -ing → 去 e 加 ing 的还原 (computing→compute)
  -ed / -d (trained→train)
  -es / -s (studies→study, networks→network)
  -er / -est (faster→fast)
不规则形态由 lemma.en.txt 覆盖(went→go 等),前端不再自维护小表 (data→datum 不做)
多候选全部与用户词库集合求交集，命中即高亮
术语表匹配规则: 划词为单词时按 lemma 精确匹配 term；划词为短语时按原文精确匹配 term（2-gram 术语不做 lemma 化）
```

### 8.4 SM-2 间隔重复

- 参数：EF 初始 2.5（下限 1.3）；复习按钮三档 → 质量 q：忘了=2 / 模糊=3 / 记得=5
- 更新（标准 SM-2，EF 公式适用**所有** q）：`q<3 → interval=1d 重来`；否则 `interval = interval==0?1 : interval==1?6 : round(interval*EF)`；恒有 `EF += 0.1 - (5-q)*(0.08+(5-q)*0.02)`（q=2→-0.32，q=3→-0.14，q=4→0，q=5→+0.1），EF 钳制下限 1.3；每次复习结果写入 review_logs
- 到期查询：`SELECT * FROM words WHERE user_id=? AND stage<2 AND due_at<=now ORDER BY due_at`
- 复习卡片：正面 = 词 + 音标；背面 = 释义 + **原句语境回显**（随机一条 occurrence）+ 本文标题

### 8.5 生词正文高亮

- pdf.js textLayer 渲染完成后，对可见 ±2 页的 span 做词级拆分（正则 `[A-Za-z][A-Za-z'-]*`）
- 拆分后 span 与词库 lemma 集合（内存 Set，词库变更时刷新）匹配 → 包裹高亮 span（三档 class）
- 跨 span 的词（pdf.js 断行）V1 不处理（已知限制，记录到风险表）
- OCR 页：对叠加层 span 做同样处理

### 8.6 批注坐标系与写回

- 一律存 **PDF 用户空间坐标**（pt，原点左下）；渲染时 `viewport.convertToViewportPoint` 映射
- 连线：SVG `<path>` 贝塞尔 `M锚点 C 控制点1 控制点2 卡片边缘`，控制点取两点中垂线偏移；拖动时实时重算
- 写回（pypdf ≥6 官方 API，均已核实）：`Highlight(rect=包围盒, quad_points=ArrayObject([...]))`（**全关键字参数**；每个锚点矩形一个 quad=[x1,y1,x2,y1,x1,y2,x2,y2]，多行高亮=8×N 顺次串联；`highlight_color` 可指定批注色）→ `writer.add_annotation(page_number, anno)`；`Text(rect, text=卡片内容前500字)` 的**返回值**作 `Popup(parent=...)`（官方确认返回值即插入对象、专用于 popup parent，且 /Popup 会自动回写父注释引用）；中文 /Contents 走 UTF-16BE 无碍；输出副本 `xxx_批注版.pdf`，不修改原文件。**不用 FreeText 承载中文可见文本**（核心字体无 CJK 字形，历史 issue）

### 8.7 OCR 管道（RapidOCR worker）

```
上传 → 前端抽样检测 is_scanned → POST /api/papers/{id}/ocr
  → server: ocr_status=pending, 拉起 worker 子进程（已在运行则投递任务）
  → worker: pypdfium2 逐页渲染(scale≈2.8 即 200dpi 起步, 灰度; PDFium 非线程安全→单线程串行)
       → RapidOCR(det+rec; PDF 页方向恒正可 use_cls=False 提速,遇旋转页再开 cls)
       → 行级结果: RapidOCROutput.boxes(N×4×2 四边形[左上,右上,右下,左下],像素坐标原点左上)+txts+scores
    → 段落聚合: 同列(x重叠>60%)+行距<1.6×行高 → 合并为 block
    → 坐标: 像素坐标 ÷ 渲染 scale → PDF 用户空间(y 轴翻转; 注意 RapidOCR 默认预处理
       max_side_len=2000 会缩放输入,需确认 bbox 已映射回原图坐标——M0 验证)
    → 每完成 1 页: 追加一行页级 NDJSON 至 blocks.ndjson（JSON 数组无法追加, NDJSON 支持断点续跑）
       + 更新 pages_done（前端轮询 1s, 由 sidecar 统一写库避免跨进程写锁）
  → 全部完成: ocr_status=done, 触发术语表 TF-IDF(基于 OCR 文本)
  → worker 空闲 60s 自动退出
失败: 任页连续失败 3 次 → papers.ocr_status=ocr_docs.status=failed, 错误写入 ocr_docs.error
重试: POST /api/papers/{id}/ocr/retry 跳过已完成页(依据已有 NDJSON 行)
恢复: 应用启动时扫描 papers.ocr_status=running 残留行 → 重置为 pending 入队(幂等续跑)
状态源裁决: papers.ocr_status 为权威状态源(UI 轮询/启动恢复/§9 ocr-status 端点均读它);
           ocr_docs.status 为任务明细副本(engine/pages_done/pages_total/error), 由 sidecar
           单写连接在事务内同值双写, worker 子进程不写库(仅回报进度)
删除: 论文删除时终止其 OCR 任务并删除 {数据目录}/ocr/{paper_id}/
```

- blocks.ndjson（每行一页）结构：

```json
{"paper_id": 10, "page": 1, "dpi_scale": 2.8,
 "blocks": [{"bbox": [x0, y0, x1, y1], "conf": 0.96,
   "text": "We propose a novel attention mechanism...",
   "lines": [{"bbox": [0,0,0,0], "text": "...", "conf": 0.97}]}]}
```

- 叠加层：前端按 block 渲染透明 `<span>`（绝对定位 + bbox 映射），`user-select: text`，选词坐标由 span 的 bbox 反算回 PDF 空间

### 8.8 备份与恢复

- 导出：zip = `data.json`（全部业务表按 user 过滤的 JSON dump）+ `files/`（该账号 PDF）
- 导入：校验 zip 结构 → 事务写入（自增 id 全量重映射；文件按 file_hash 合并；username 冲突自动加后缀改名并在 report 列明）→ 自动刷新
- 数据目录迁移：复制 → 校验（文件数/大小抽检）→ 更新配置 → 删原目录 → 重启 sidecar；任一步失败保留原目录
